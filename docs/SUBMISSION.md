# Track 3 submission preparation — OmegaRuby

**Project:** CONTINUUM  
**Track:** Track 3 — Company Brain  
**Tagline:** A company brain that knows when decisions become outdated—and helps the right people respond.

Company knowledge often preserves documents but loses the relationships between decisions, assumptions, delivery gates, customer promises and current owners. CONTINUUM models that connected context in FalkorDB and turns a changed prerequisite into a reviewable response.

The demonstration uses fictional Northstar Systems. An export service security approval is withdrawn. CONTINUUM preserves the approval that justified the earlier launch decision, traces bounded dependency paths to Atlas milestones and customer commitments, surfaces an old-owner/new-owner conflict with both sources, and proposes internal review work. A human selects tasks to approve; the application persists their owner, triggering event, source evidence and decision/commitment links. A fresh session can recover what changed and what remains unresolved from FalkorDB.

FalkorDB is essential: dependency traversal, source retrieval, ownership, history and follow-up records use real graph queries. Removing a relevant dependency changes impact; adding unrelated contextual relationships does not. Database outages produce an unavailable state. One bounded model agent investigates with typed tools; task approval is an explicit application path.

**Distinctive contribution:** evidence aging becomes an accountable response workflow, with the prior rationale retained. The system flags decisions for review rather than declaring them wrong. Structured fixture relationships are disclosed; this is not a claim of arbitrary-document extraction or enterprise-scale deployment.
